# 触发、任务与计划编排

触发能力决定数字员工何时开始工作，任务能力决定工作如何被管理。FDE 不应只设计聊天入口，真实交付要让工作能被看见、能被分派、能被查看。

## 对话触发

对话适合低门槛启动：

- 用户临时提问。
- 用户补充材料。
- 用户要求员工生成报告或查询信息。
- 用户解释一个异常任务。

对话触发的限制是上下文容易散落。只要任务需要持续推进，就应进入任务看板。

## 任务看板

任务看板用于围绕任务分配、状态和活动进行协作。

适合场景：

- 人给员工派活。
- 员工把后续工作交给另一个 team 内员工。
- 周期巡检发现异常后生成待处理任务。
- 外部事件进入后形成可跟踪事项。

FDE 设计任务看板场景时，应优先验证这些闭环：

- 创建任务后，指定员工能看到并处理。
- 员工处理后，任务状态和活动记录能反映进展。
- 任务结果能连接到数据、消息或交付物。

## 计划任务

计划任务用于按时间、日历或周期触发任务。

适合场景：

- 每日经营简报。
- 每周行业周报。
- 每日应收巡检。
- 每周内容选题。
- 节假日或业务日历相关提醒。

Calendar Sources 归入计划任务。FDE 应把它作为计划任务的前置或扩展条件，例如「使用工作日日历决定是否触发日报」。

计划任务的最小验证路径：

1. 在 team 内创建一个计划任务。
2. 绑定目标员工和任务描述。
3. 设置固定时间或日历条件。
4. 触发一次运行。
5. 查看员工是否产出预期结果。

## Webhook

Webhook 用于通过外部事件触发系统能力。

适合场景：

- 表单提交后创建线索处理任务。
- 外部系统状态变化后通知员工。
- 告警事件进入后生成排查任务。

Webhook 只负责事件进入，不等同于完整业务流程。FDE 应在 CRIDO 中继续写清 Reference、Input、Do 和 Output。

## 电子邮箱

电子邮箱用于通过邮件入口接收、处理和输出信息。

适合场景：

- 客户订单邮件解析。
- 系统通知邮件整理。
- 邮件附件进入数据处理流程。
- 周期性报告通过邮件发送或归档。

邮件场景应优先确认：入口地址、路由规则、附件处理、处理结果和结果送达方式。
