# 数据、知识与业务对象

FDE 需要区分三类东西：业务数据、业务知识、业务对象关系。它们解决的问题不同，不能混成「给员工一些资料」。

## 业务数据

业务数据是会被查询、筛选、更新或统计的结构化对象，例如客户、订单、回款、工单、设备、项目、内容计划。

判断是否需要结构化数据时，看三个问题：

- 是否有多人或多个数字员工围绕同一对象协作。
- 是否需要状态、字段、负责人或时间维度。
- 是否需要周期巡检、统计或写回。

如果答案为是，应优先设计数据表、字段、权限和验证样例。

## 知识库同步

知识库同步用于同步和使用 team 知识资料。

适合场景：

- 产品资料问答。
- 历史项目资料检索。
- 客户服务 FAQ。
- 企业制度、流程和口径查询。

知识库方案应确认：资料范围、同步入口、同步范围、可见范围、检索样例和结果质量。

## Reference 与数据地基的关系

CRIDO 中的 Reference 不等于数据。Reference 是执行依据，数据是操作对象。

例如：

- 交期计算规则是 Reference。
- 订单表是业务数据。
- 客户特殊要求文档是 Reference。
- 客户记录是业务数据。

FDE 写 skill 时，应明确员工先读哪些 Reference，再读写哪些业务数据。

## 业务对象关系

当客户场景涉及大量对象关系时，可以单独设计业务对象关系图。例如制造业场景中，客户、订单、物料、库存、设备、工序、交付和回款之间会形成复杂关系。

本指南不默认要求每个项目做本体建模。只有当表结构和知识文档无法稳定表达对象关系时，再把它作为高阶方案补充。
