# 验收与质量标准

FDE 验收的对象不是「模型回答得像不像」，而是业务闭环是否在 team 内真实跑通。

## 最小验收单位

每个验收用例必须能回答：

- 谁触发。
- 哪个员工处理。
- 使用了哪些 Reference。
- 读取了哪些 Input。
- 调用了哪些能力。
- 产出了什么 Output。
- 用户在哪里看到结果。

如果这些问题不能回答，就不应进入正式交付。

## 按能力类型验收

| 能力类型 | 验收重点 |
| --- | --- |
| 任务看板 | 任务创建、指派、状态变化、结果可见 |
| 计划任务 | 时间或日历触发、目标员工、执行结果 |
| Webhook | 外部事件进入、字段解析、后续任务或结果 |
| 电子邮箱 | 邮件进入、附件处理、结果输出 |
| browser_use | 页面打开、登录态、业务页面操作、可观察结果 |
| WebSkill | 高频网页流程可复用，不需要每次重新探索 |
| Secret | 凭据由保险箱管理，文档不暴露真实秘密 |
| 设备 | 设备可用、状态可见、与执行能力组合成功 |
| 内网服务 | 私有服务可发现、可访问、结果可验证 |
| Vibe Coding | 应用能创建、运行、构建、发布和访问真实数据 |
| 知识库同步 | 资料同步成功，检索结果能回答指定问题 |
| compute_use | 执行环境可用，任务结果能被观察或交付 |
| octopus-cli | 命令能完成目标动作，输出可用于后续步骤 |

## 正式交付前必须处理的情况

以下情况只能作为试点或演示，不应作为正式交付结果：

- 只有页面截图，没有跑通业务闭环。
- 只有代码或包名，没有实际使用记录。
- 只有一次自然语言回复，没有任务、数据、文件、页面或消息结果。
- 只验证了单点动作，没有验证前置条件和结果落点。
- 依赖另一个能力，但另一个能力还没有确认。

## 验收记录格式

```text
用例编号：
业务故事：
Cue：

Do：
Output：

当前结论：
待补充：
```
